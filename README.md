# Clip Sync

Windows、iPhone、Androidのブラウザ間でテキストを共有する静的サイトです。ネイティブアプリ、アカウント、ビルド環境は不要です。画面のボタンで貼り付け・送信・コピーを行います。自動的なクリップボード監視は行いません。

## 使い方

1. 1台目でサイトを開き、端末名を確認して「接続コードを作る」を押します。この端末がホストです。
2. 2台目でQRコードをカメラで読み取るか、同じサイトを開いて10文字の接続コードを入力し、「参加」を押します。
3. ホストに表示される接続リクエストを「承認」します。3台目以降も同じ手順で参加できます。
4. テキストを入力または「貼り付け」で読み込み、「送信」を押します。受信した端末で「コピー」を押して使います。

ホストのタブは開いたままにしてください。参加端末同士のテキストはホスト端末を経由します。履歴は各タブのメモリに最大50件保持し、再読み込みやタブを閉じると消えます。端末名のみブラウザのローカルストレージに保存します。

## GitHub Pagesで公開

1. このリポジトリの **Settings → Pages** を開きます。
2. **Build and deployment** の **Source** を **Deploy from a branch** にします。
3. **Branch** で `main` と `/ (root)` を選んで保存します。
4. 表示された `https://Y-Sebastian263.github.io/clip_sync/` にWindows、iPhone、Androidからアクセスします。最初の公開には数分かかることがあります。

`index.html`、`styles.css`、`app.js`、`assets/vendor/` をそのまま配信します。サーバー側のコードや環境変数はありません。ローカル開発時は `python3 -m http.server` などでHTTP配信し、同じPCの `http://localhost:8000` で確認できます。スマートフォンから試す際はHTTPSのPages URLを使ってください。

## 通信とプライバシー

- PeerJSの公開仲介サーバー（`0.peerjs.com`）で接続先を探し、WebRTC DataChannelを確立します。端末名、接続ID、WebRTCの接続情報は仲介サーバーを通ります。送受信するテキスト本文は仲介サーバーやGitHubに保存しません。
- 端末間の通信にはWebRTCの暗号化が使われます。QRコードと接続コードは、その場にいる信頼できる相手にだけ共有してください。参加にはホスト側の承認が必要です。
- PeerJS Cloudは外部サービスです。停止・制限・仕様変更時は接続できません。企業ネットワークや厳しいNAT環境ではWebRTCの直接接続に失敗することがあります。この構成にはTURN中継サーバーを用意していません。
- ホストを閉じると接続が切れます。テキストは各タブのメモリにだけ残り、同期した永続履歴はありません。送信上限は1回16 KiBです。

## クリップボードとブラウザの制約

- Clipboard APIは原則HTTPSなどの安全なコンテキストで動きます。読み取り・書き込みにはユーザー操作や権限が必要で、ブラウザ・設定・操作状況によって拒否されます。自動監視・バックグラウンド共有はできません。
- WindowsのChrome/EdgeとAndroidのChromeでは、ボタンからの読み取り・書き込みが利用できる場合があります。権限の確認が表示されることがあります。
- iPhoneのSafariでは、クリップボードアクセスがより厳しく、貼り付け許可が表示されたり、`readText()` が使えなかったりします。その場合は入力欄を長押しして「ペースト」を選んでください。コピーに失敗した場合は選択済みのテキストを手動でコピーします。
- QRコードはスマートフォンの標準カメラでURLを開く方式です。カメラを使えない場合はコードを手入力できます。
