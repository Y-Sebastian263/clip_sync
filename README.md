# Clip Sync

Windows、iPhone、Androidのブラウザ間でテキストを共有する静的サイトです。ネイティブアプリ、アカウント、ビルド環境は不要です。画面のボタンで貼り付け・コピーを行い、入力欄は500ms周期で自動同期します。自動的なクリップボード監視は行いません。

## 使い方

1. 1台目でサイトを開き、端末名を確認して「接続コードを作る」を押します。この端末がホストです。
2. 2台目でQRコードをカメラで読み取るか、同じサイトを開いて10文字の接続コードを入力し、「参加」を押します。
3. ホストに表示される接続確認ポップアップで端末名を確認し、「承認」または「拒否」を選びます。3台目以降も同じ手順で参加できます。
4. テキストを入力または「貼り付け」で読み込むと、500ms周期で接続端末へ自動同期します。空欄への変更も同期します。
5. どの端末でも「コピー」で現在の送受信テキストを、その端末自身のクリップボードへコピーできます。成功するとその端末の履歴に記録されます。履歴の「呼び出し」で入力欄へ復元すると、その内容も自動同期します。

ホストのタブは開いたままにしてください。参加端末同士のテキストはホスト端末を経由します。履歴はコピー成功時だけ各タブのメモリに最大50件保持し、再読み込みやタブを閉じると消えます。端末名のみブラウザのローカルストレージに保存します。

## GitHub Pagesで公開

1. このリポジトリの **Settings → Pages** を開きます。
2. **Build and deployment** の **Source** を **Deploy from a branch** にします。
3. **Branch** で `main` と `/ (root)` を選んで保存します。
4. 表示された `https://Y-Sebastian263.github.io/clip_sync/` にWindows、iPhone、Androidからアクセスします。最初の公開には数分かかることがあります。

`index.html`、`styles.css`、`app.js`、`assets/vendor/` をそのまま配信します。サーバー側のコードや環境変数はありません。ローカル開発時は `python3 -m http.server` などでHTTP配信し、同じPCの `http://localhost:8000` で確認できます。スマートフォンから試す際はHTTPSのPages URLを使ってください。

## 通信とプライバシー

- PeerJSの公開仲介サーバー（`0.peerjs.com`）で接続先を探し、WebRTC DataChannelを確立します。端末名、接続ID、WebRTCの接続情報は仲介サーバーを通ります。送受信するテキスト本文は仲介サーバーやGitHubに保存しません。
- 端末間の通信にはWebRTCの暗号化が使われます。QRコードと接続コードは、その場にいる信頼できる相手にだけ共有してください。参加にはホスト側の承認が必要です。
- PeerJS Cloudは外部サービスです。停止・制限・仕様変更時は接続できません。企業ネットワークや厳しいNAT環境ではWebRTCの直接接続に失敗することがあります。この構成にはTURN中継サーバーを用意していません。
- ホストを閉じると接続が切れます。テキストは各タブのメモリにだけ残り、同期した永続履歴はありません。送信上限は1回16 KiBです。

## クリップボードとブラウザの制約

- Clipboard APIは原則HTTPSなどの安全なコンテキストで動きます。読み取り・書き込みにはユーザー操作や権限が必要で、ブラウザ・設定・操作状況によって拒否されます。OSクリップボードの自動監視は行いません。バックグラウンド中の同期継続も保証できません。
- WindowsのChrome/EdgeとAndroidのChromeでは、ボタンからの読み取り・書き込みが利用できる場合があります。権限の確認が表示されることがあります。
- iPhoneのSafariでは、クリップボードアクセスがより厳しく、貼り付け許可が表示されたり、`readText()` が使えなかったりします。その場合は入力欄を長押しして「ペースト」を選んでください。コピーに失敗した場合は選択済みのテキストを手動でコピーします。
- QRコードはスマートフォンの標準カメラでURLを開く方式です。カメラを使えない場合はコードを手入力できます。

## 自動同期と自動復旧

- 通常は変更された内容だけを500ms周期で送ります。受信を新しい編集として扱わず、接続ごとに送信済みの更新を記録して無限エコー・定常的な同一内容の再送を防ぎます。接続開始・復帰時は状態確認のため最新内容を再送することがあります。
- 更新には時刻と端末識別子を付け、同時編集は更新番号が大きい側、同値なら識別子順で決定して全端末を収束させます。端末時計にずれがある場合、実際の編集時刻順とは異なることがあります。共同文書のような文字単位のマージはしません。
- 切断中の入力も保持し、再接続時に双方の更新を比較します。日本語変換中や16 KiBを超える入力は同期を保留します。上限を超えたら入力を短くしてください。
- 初回接続時は「○○が接続しました」、切断時は「接続が切れました。再接続中…」、承認済み端末の復旧時は「再接続しました」と通知します。
- DataChannelのclose/error、WebRTCのconnectionstatechange/iceconnectionstatechange、PeerJS仲介接続の切断を監視します。再試行は約1秒から指数的に延長し、最大30秒＋最大0.5秒の揺らぎを入れます。接続開始が20秒以上進まなければ作り直します。
- online、visibilitychangeでの前面復帰、pageshowではすぐに復旧処理と再同期を試みます。offline中は再試行を止めます。前面では10秒間隔の生存確認を行い、35秒応答がない接続を作り直します。初回の承認待ちも生存確認を行うため、承認を急ぐ必要はありません。
- 初回承認時にランダムな復帰トークンを暗号化されたDataChannelで発行し、同じタブの一時的な再接続だけ再承認を省略します。端末名だけでは自動承認しません。トークン・本文・履歴はメモリのみで、再読み込み後は参加・承認が必要です。「拒否」された参加端末は再試行を停止します。
- 「接続を終了」した側は自動再接続しません。相手側は切断として復旧を試みるため、利用を終える際は両端末で終了してください。ホストを閉じたり再読み込みした場合、元の部屋は復旧できません。新しいコードで参加し直してください。

### バックグラウンドとブラウザ差

完全ブラウザ版のため、iPhone/Safariのアプリ切り替え・画面ロック、Androidの省電力、Windowsのスリープやタブ休止などでJavaScript、タイマー、WebRTCが停止する可能性があります。500msは前面動作時の目標周期で、通信遅延やブラウザのタイマー制限によって遅れます。前面に戻ったときに接続を確認して復旧しますが、相手のホスト端末も休止している場合はそちらも前面に戻してください。

Service Workerは導入していません。将来PWAや静的キャッシュに利用しても、バックグラウンドでWebRTCを維持する保証にはなりません。OSによってタブが破棄された場合はメモリの内容も失われます。

コピーはユーザーが押したボタンからClipboard APIを直接呼びます。HTTPS、権限、ユーザー操作の条件はブラウザごとに異なります。失敗時は手動コピーを案内し、成功を確認できないため履歴には記録しません。接続コードのコピーも本文履歴には入りません。

参考: [PeerJSの接続API](https://peerjs.com/client/api/peer)、[Clipboard APIの制約](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)、[Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。

## 開発時の検証

Node.jsがある環境で `node --test tests/app.test.cjs` を実行します。仮想時計・模擬PeerJS/DataChannelで、複数端末同期、重複送信防止、同時編集、ICE切断、ネット復旧、前面復帰、承認維持、コピー履歴、呼び出し、日本語変換を検証します。配信時にNode.jsは不要です。

実機ではWindows Chrome/Edge、iPhone Safari、Android Chromeで、双方向編集・コピー、機内モードからの復帰、画面ロックからの復帰を確認してください。模擬テストは各OSの休止制御や実ネットワークの到達性を保証しません。

任意の実ブラウザ検証は、PlaywrightとChromiumを用意して `node tests/browser-smoke.cjs` を実行します（既存Chromeを使う場合は `CHROME_PATH` に実行ファイルを指定）。一時的なローカル配信と公開PeerJS仲介サービスへの接続を使い、2タブ間の実WebRTC通信、双方向同期、offline/onlineイベントによる接続作り直し、コピーと呼び出し、画面幅を検証します。実ネットワーク断やOS休止の代替テストではありません。
