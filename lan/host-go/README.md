# ClipSync Host.exe — Windows LANホスト（試作版）

ClipSyncの**2つの利用方法**のうち、こちらは **同一LAN内だけで共有する「PCホスト版」** です。

- Windows PCで `ClipSyncHost.exe` を起動すると、共有ボードが使えるようになります。**Node.js / mkcert / Python のインストールは不要**です。
- PCの管理画面は自動的に `http://localhost:4478/` で開きます。これはPC内部 (`127.0.0.1`) のみで使うためのHTTPです。
- スマホ・iPad・別のPCは `https://<ホストのLAN IP>:4477/` へブラウザで接続します。**LAN向け通信はHTTPS必須**です。
- 登録は、最初の1回だけホストPCの画面で申請端末の6桁照合番号を確認・承認。以後は最大180日間、同じブラウザから自動認証できます。端末別に解除可能です。
- 登録済み端末のオンライン表示・最終確認日時、共有テキスト同期、最大50件の共有掲示板、mDNS（`.local`）でのホスト通知に対応しています。
- メール・氏名・アカウント不要。クリップ本文をクラウドやディスクに保存しません。ホストを終了すると共有本文は消えます。

## 起動方法

1. Windows 10/11 x64のPCを、プライベートなWi-Fiまたは有線LANに接続します。
2. 配布物の `ClipSyncHost.exe` を起動します。コンソール画面を閉じるとホストも停止します。複数のLANがある場合、表示される番号で使用するLANを選びます。
3. ブラウザの `http://localhost:4478/` がホスト管理画面です。開かない場合は手入力します。
4. Windowsファイアウォールに追加する場合は、**TCP 4477 をプライベートネットワーク／ローカルサブネットのみに制限**します。mDNSを利用するなら UDP 5353 もプライベートネットワーク／ローカルリンクだけに限定してください。**ルーターのポート転送・パブリックネットワークでの許可は禁止**。
5. スマホ・iPad・別PCで、ホスト画面に表示されるLAN用HTTPS URLを開きます。証明書の初回設定が必要です（次の項目を確認）。
6. 端末名（氏名不要）を入力し、ホスト管理画面で**双方の6桁番号が一致することを確認**してから承認します。次回以降は同じURL・ブラウザなら自動認証されます。

## 初回のHTTPS証明書設定（重要）

ClipSyncは外部の公開サーバーを使わないため、ホストごとの**ローカルCA**が発行した証明書でLAN通信を暗号化します。インターネットの公開CAとは異なり、iPhone/iPad/Android/別PCはこのCAを最初から信頼していません。

- ホスト管理画面の「公開CA証明書を保存」か、PCの `%LOCALAPPDATA%\ClipSyncHost\ClipSync-RootCA.cer` から**公開CA証明書だけ**を取り出します。
- 端末へUSBや信頼できるファイル転送などで安全に渡し、証明書の指紋（ホストのコンソールに表示されるSHA-256）が一致することを確認してから信頼します。
- iPhone/iPadではプロファイルをインストールしたあと、**設定 → 一般 → 情報 → 証明書信頼設定**で完全信頼を明示的に有効にする必要があります。Androidは端末や管理ポリシーによって設定が異なります。
- **HTTPSの警告を無視してそのまま接続することは推奨しません。** 予期せぬルートCAをインストールしないでください。
- **証明書の有効期限は約1年**です。ホストLAN IPが変わったときも新しいローカルCAが発行され、端末側で改めて信頼設定が必要になることがあります。既存の公開CAは不要になったら端末の信頼ストアから削除してください。
- このEXEではCA署名用の**秘密鍵をディスクへ保存しません**。サーバーTLS秘密鍵 (`server.key`) はホストPC内に保存されるため、PCのログインアカウントを保護してください。

## セキュリティ設計と限界

- LAN IPと127.0.0.1のみにサービスをバインド。LAN HTTPSはホストPCと同じIPv4サブネットの送信元だけを許可。IPv6の公開待受けをしません。WindowsファイアウォールのプライベートLAN制限も必須です。
- 管理APIは `127.0.0.1:4478` 経由だけ。ローカルブラウザで承認・登録解除します。ホストOSにログインできる人には管理権限があるため、PCの画面ロックを有効にしてください。
- 接続コードは端末ごとに独立。Cookieは Secure / HttpOnly / SameSite=Strict。認証トークンはランダムで、サーバーはSHA-256ハッシュだけ保存します。ローカルの `devices.json` に端末名・登録時刻・ハッシュを保存します。
- JSON/Originの厳格なチェック、CSP、XSS対策（ブラウザ側はtextContent表示）、投稿サイズ上限、接続申請／書き込み回数制限を設けています。
- mDNSはホスト識別子・IP・ポートのみ通知し、ネットワーク内の全機器はスキャンしません。ブラウザから周辺ホストを自由に一覧表示することはできません。mDNS・`.local`が利用できない場合はIPアドレスで接続します。
- VPN・Wi-Fi隔離・複数ルーター・証明書信頼設定・ファイアウォール・OSの省電力制御により接続できないことがあります。
- セキュリティ境界はIPだけではありませんが、ホストPC自体に悪意あるプログラムが存在する場合までは防げません。同一LANへの侵入者がmDNS情報を偽造することも可能なので、証明書を信頼できる方法で検証してください。
- コード署名されていない試作版のEXEにはWindowsのSmartScreen警告が表示されることがあります。出所とSHA-256を確認してください。

## ヘルプ / オプション

```
ClipSyncHost.exe --help
ClipSyncHost.exe --ip 192.168.1.10
ClipSyncHost.exe --port 4477 --admin-port 4478
ClipSyncHost.exe --no-browser --no-mdns
```

設定は既定で `%LOCALAPPDATA%\ClipSyncHost` に保存します。必要に応じて `--data-dir` で変更できます。IPを変更すると証明書が再発行される場合があるため、ルーター側でホストPCに固定DHCP割当を設定するのが便利です。

## ソースコードから再現ビルド

このホストはGo標準ライブラリのみを使用します。`public/` のHTML/CSS/JSを埋め込むため、ホストEXEをコピーするだけで動作します。

```bash
cd lan/host-go
go test ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o ClipSyncHost.exe .
```

**一般配布用はGitHub Actionsで最新のサポート対象Go 1.27.3（2026-11-04時点）を使用してビルド**します。ローカル環境が古いGoの場合、生成EXEは技術確認用としてのみ扱ってください。

既存のNode.jsベースLAN試作版は `lan/server.cjs` に残しています。データファイルは同じ `devices.json` 形式を使いますが、認証Cookieの形式が異なるため、**Node版で登録した端末の自動認証はそのまま引き継がれません**。
