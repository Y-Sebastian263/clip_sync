# ClipSync LAN — 安全性を優先したローカル共有ボード

既存の `Y-Sebastian263/clip_sync` をLAN専用で使うための**独立した試作版**です。既存GitHub Pages版のコードや公開ページは変更しません。

- ホストPCでNode.jsの小さなHTTPSサーバーを起動。Windows PC・スマホ・iPadから、**同一サブネット内**で共有テキストと50件までの掲示板を操作できます。
- **会員登録・氏名・メールアドレス不要**。最初の1回だけホストPCが端末名を見て承認。以降はブラウザに保存されたHttpOnly Cookieで自動接続。
- 公開PeerJS・クラウドデータベース・CDN・追跡タグ・外部通信を使用しません。接続はホストPCのローカルIPへのHTTPSのみです。
- 掲示板とテキストは**ホストPCのメモリだけ**に置き、終了すると消えます。端末の認証ID・端末名・認証トークンのSHA-256ハッシュだけホストPCの `data/devices.json` に保存します。
- ホストPCは `https://localhost:4477/` を開いて承認・端末登録解除。ほかの端末は `https://<ホストのLAN IP>:4477/` を開きます。別LANやインターネット越しの直接利用はできません。

> **重要:** GitHub PagesだけでLAN限定のサーバー／接続仲介まで完結させる構成ではありません。サービスを使う各グループのホストPCがこのサーバーを起動する必要があります。端末のブラウザだけでホストにもなる完全Web方式ではありません。

## 動作要件

- Node.js 20以上（Windows 10/11を想定。ほかのOSもNode.jsで起動可）。npmパッケージのインストールは不要。
- HTTPS用証明書。**HTTPへのフォールバックはありません。** 必ず端末側でも証明書を検証できるよう信頼設定してください。
- ホストと端末が通信できる同じIPv4サブネット内。ゲストWi-Fiの端末分離／APアイソレーションが有効だと接続できません。

## Windowsでの起動

1. ホストPCにNode.js 20以上と [mkcert](https://github.com/FiloSottile/mkcert) をインストールします。
2. `start-windows.ps1` をPowerShellで実行します。候補IPが複数ある場合は `./start-windows.ps1 -LanIp 192.168.1.23` のように指定します。
3. 初回起動時にローカルHTTPS証明書を作成します。ホストPCのブラウザで `https://localhost:4477/` を開いて管理します。
4. Windows DefenderファイアウォールはTCP 4477番を**プライベートプロファイルかつローカルサブネットだけ**に許可し、パブリックプロファイルには許可しないでください。ルーターのポート転送は禁止。
5. スマホ・iPadで同じLANへ接続し、ホスト画面にある `https://<ホストIP>:4477/` を開きます。端末名を入力して「接続を申請」、ホストPCと端末画面の6桁照合番号が一致することを確認して「承認」。次回以降は同じブラウザを開くだけで接続できます。

**iPhone/iPad/Androidの証明書信頼設定:** mkcertが作成した**公開CA証明書**（`mkcert -CAROOT` で表示したフォルダにある `rootCA.pem`）だけを、物理的に信頼できる方法で各端末へ渡してインストールしてください。iOSではプロファイルをインストール後、設定の「証明書信頼設定」で明示的に完全信頼を有効にする必要があります。Androidの手順は端末・OSによって異なります。**`rootCA-key.pem` は秘密鍵なので絶対に配布・共有しないでください。** このローカルCAを信頼すること自体が信頼範囲を増やすため、慎重に扱ってください。公開サービス向けには、代わりに正規の信頼済みCAで発行した証明書を運用する方法も検討できます。

PowerShellの実行ポリシーでスクリプトがブロックされる場合は、内容を確認したうえで自分でPowerShellから必要なコマンドを実行してください。ポリシーを恒久的に緩めることは推奨しません。

### Windows以外、またはすでに証明書がある場合

```bash
export CLIPSYNC_HOST_IP=192.168.1.23
export CLIPSYNC_TLS_CERT=/path/to/lan.crt
export CLIPSYNC_TLS_KEY=/path/to/lan.key
node server.cjs
```

証明書は `CLIPSYNC_HOST_IP` に指定したIPアドレスのSANを含む必要があります。ホストIPが変わった場合は証明書を作り直してください。無効な証明書の警告を無視しての利用は推奨しません。

## ユーザー登録・自動接続・取り消し

初回: 利用端末が参加申請 → ホストPC（ループバックからのみ管理可能）が承認 → 強力なランダムトークンが端末のSecure/HttpOnly/SameSite=Strict Cookieに保存。

再訪: Cookieで自動認証。ブラウザのCookieを消した・プライベートモードを使った・別ブラウザに変えた場合は再承認が必要です。認証は登録から180日で期限切れになります。ホストPCの「登録解除」で即時無効化できます。

## 主な防御とその限界

- **LAN限定:** 同じネットマスクの送信元IPv4だけを許可。ホスト名チェックでDNSリバインディングを抑制。IPv6やインターネット向けリスナーは開きません。ルーターが転送や送信元IP変換をする場合などは、ネットワーク構成によって例外があり得ます。Windowsファイアウォールも併用してください。
- **HTTPS必須:** TLS 1.2以上。認証CookieはSecure/HttpOnly/SameSite=Strict。配布ZIPに秘密鍵・共有パスワードは含みません。
- **認証:** 初回ホスト承認、推測困難な認証トークン、サーバー保存はハッシュのみ、端末ごとの取り消し、180日期限。
- **Web攻撃:** API書き込みで同一OriginとJSON型を強制、CORS不許可、CSP設定、ユーザー入力はDOMのtextContentで表示、ファイルルーティングは固定許可リスト。
- **荒らし・DoS:** 参加申請はIPあたり毎分4回、承認待ち20件、端末登録32件、SSE接続40件、テキスト16KiB、掲示板50件。**同一LAN上の悪意ある端末による大量接続やネットワーク妨害を完全には防げません。**
- **プライバシー:** クリップ本文はディスク保存・クラウド送信しません。ただし本文に個人情報を入力すれば、それを共有することになります。接続時はホストがIPアドレスを一時的に扱い、端末の呼び名と登録日時はローカル保存されます。
- **物理アクセス:** ホストPC上のローカル管理画面はパスワード不要です。ホストPCの利用者アカウントをOSのパスワードなどで保護してください。

## 既存ClipSyncとの違い

| 項目 | 既存のGitHub Pages版 | このLAN試作版 |
|---|---|---|
| 接続 | 公開PeerJS仲介＋WebRTC | ホストPCとのHTTPS＋SSE/POST |
| インターネット | 仲介時に必要 | LAN通信に不要 |
| 同一LAN限定 | いいえ | 同一IPv4サブネット内のみ |
| 初回承認 | あり | あり |
| 再読み込み後の自動承認 | なし | あり（180日） |
| 掲示板への複数投稿 | なし | 50件まで（メモリのみ） |
| ホストPCの追加ソフト | 不要 | Node.jsとローカルHTTPSサーバーが必要 |

**既存版の動作をそのまま維持してLAN限定にすることは技術的にできません。** 端末通信の仕組みはWebRTCからローカルHTTPSの同期に切り替えていますが、共有・コピー・貼り付け・複数端末同期という体験は残しています。

## 開発・テスト

```bash
node --test tests/*.test.cjs
```

テストは一時的なテスト用HTTPS証明書（OpenSSLがある環境）を生成し、ホストとゲストの通信を模擬します。実際のWindows/iPhone/iPad端末の証明書信頼やWi-Fi端末分離は別途実機テストが必要です。

## 制約・今後の候補

- ブラウザ上のクリップボード自動監視はしません。貼り付け・コピー操作にはブラウザ権限が必要です。
- ホストPCの停止や証明書の期限切れで利用不可。ホストPCを起動したままにする必要があります。
- セッションが有効でもSafariのバックグラウンドではリアルタイム更新が停止する場合があります。前面復帰後にSSEが再接続します。
- 端末間の単一テキストを同時編集した際は競合を表示して、どちらを採用するかユーザーに選んでもらいます。文字単位の同時編集マージはありません。
- データ保存や自動ホスト発見、QRコード、Windows EXE化はまだ未実装です。運用前に複数OSで実機検証してください。
